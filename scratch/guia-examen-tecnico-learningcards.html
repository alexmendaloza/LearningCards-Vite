Seccion 1: Mapa de Ubicacion del Codigo

1. Conexion a Base de Datos MySQL / XAMPP

Archivo: backend/src/config/db.js

Ahi se configura mysql2/promise, el pool de conexiones y las variables DB_HOST, DB_PORT, DB_USER, DB_PASSWORD y DB_NAME.

Respuesta: Las credenciales se leen desde .env; si no existen, usa valores compatibles con XAMPP local: localhost, puerto 3306, usuario root y password vacio.

2. Rutas del Servidor / Endpoints API

Archivo principal: backend/src/app.js

Ahi se montan los routers bajo el prefijo /api.

  • backend/src/routes/auth.routes.js
  • backend/src/routes/user.routes.js
  • backend/src/routes/deck.routes.js
  • backend/src/routes/marketplace.routes.js
  • backend/src/routes/admin.routes.js
  • backend/src/routes/system.routes.js

3. Controladores / Logica SQL

  • Login, registro y sesion: backend/src/controllers/authController.js
  • Usuarios, dashboard, perfil y reportes: backend/src/controllers/userController.js
  • Mazos, tarjetas y sesiones de estudio: backend/src/controllers/deckController.js
  • Marketplace, compras y valoraciones: backend/src/controllers/marketplaceController.js
  • Administracion, usuarios, mazos y ventas: backend/src/controllers/adminController.js

4. Encriptacion de Contrasena

Archivo: backend/src/controllers/authController.js

Funcion: register

La contrasena se cifra antes del INSERT INTO Usuario con bcrypt.hashSync(String(req.body.password), 10).

5. CORS

Archivo: backend/src/middleware/security.js

Funcion: applySecurityMiddleware

Permite que React en localhost se comunique con el backend y habilita cookies mediante credentials: true.

6. Login y Generacion de Token

Validacion: backend/src/controllers/authController.js, funciones login y adminLogin.

Token: backend/src/middleware/auth.js, funcion signIn.

El JWT se guarda en una cookie HttpOnly.

7. Seguridad y Rutas Protegidas

Archivo: backend/src/middleware/auth.js

  • requireUser: valida JWT y carga req.usuario.
  • requireAdmin: valida usuario y exige req.usuario.rol === 'admin'.

8. Pagos / Compra de Mazos

Frontend: frontend/src/pages/Platform.jsx, componente PaymentPage.

Backend: backend/src/controllers/marketplaceController.js, funcion confirmPayment.

Nota tecnica: en esta version academica el pago es simulado con tarjeta; no hay integracion real con PayPal.

9. Reportes PDF

Usuario: frontend/src/pages/Report.jsx y backend userController.report.

Creador: frontend/src/pages/reports/UserStats.jsx y backend userController.creatorStats.

Admin: frontend/src/pages/Platform.jsx, AdminPrintLayout, y backend adminController.salesReport.

El PDF se obtiene con window.print(); el backend compila los datos y el frontend renderiza una vista imprimible.

10. Axios / Comunicacion Frontend-Backend

Archivo: frontend/src/api/axiosConfig.js

Configura baseURL: 'http://localhost:3001/api' y withCredentials: true para enviar cookies al backend.

Seccion 2: Simulacion de Preguntas Capciosas

1. ¿Por que separaron Frontend y Backend?

Porque separa responsabilidades. React/Vite maneja interfaz y navegacion, mientras Express concentra reglas de negocio, autenticacion, seguridad y consultas SQL. Esto mejora mantenibilidad, permite escalar por capas y evita exponer logica sensible en el navegador.

2. ¿Que pasa si MySQL/XAMPP se apaga mientras un usuario estudia?

La interfaz puede seguir renderizando, pero las operaciones que dependen de backend fallaran: guardar sesion, consultar mazos o registrar progreso. Los controladores usan try/catch y delegan al errorHandler, por lo que se devuelve un error controlado en lugar de romper el servidor.

3. ¿Como evitan que un usuario comun entre al admin alterando React?

No se confia en el frontend. Aunque el usuario modifique rutas o componentes, los endpoints administrativos pasan por requireAdmin. Ese middleware valida el JWT, consulta el usuario real en MySQL y exige rol === 'admin'. Si no cumple, responde 403.

4. ¿Donde se demuestra que hay logica propia y no solo pantallas?

En los controladores del backend: deckController.js maneja mazos, tarjetas y sesiones; marketplaceController.js valida compras y transacciones; userController.js calcula reportes; adminController.js produce metricas administrativas.

5. ¿La contrasena esta segura?

Si. En authController.register se cifra con bcrypt antes de insertarla. En login se compara con bcrypt.compareSync. La contrasena real nunca se guarda ni se compara en texto plano.

6. Si cambio rol: 'admin' en el navegador, ¿ya soy admin?

No. El rol del frontend no concede permisos. El backend obtiene el usuario desde la cookie JWT y luego valida contra la base de datos. La autorizacion real ocurre en requireAdmin.

7. ¿El pago es PayPal real?

No. En esta version academica el flujo es un pago simulado con tarjeta. Lo tecnicamente importante es que el backend valida datos, evita compras duplicadas y registra la compra junto con la clonacion del mazo.

8. ¿Por que usan cookie HttpOnly para el JWT?

Porque reduce el riesgo de robo del token mediante JavaScript. Axios usa withCredentials: true, asi que el navegador envia la cookie automaticamente al backend.

9. ¿Como impiden que un usuario edite mazos ajenos?

En deckController.js, funciones como updateDeck usan condiciones SQL con IDMazo e IDUsuario. Si el mazo no pertenece al usuario, no se actualiza.

10. ¿El PDF se genera en backend?

No como archivo binario. El backend compila los datos y el frontend renderiza una vista imprimible. La descarga se realiza con window.print(), permitiendo guardar como PDF desde el navegador.
